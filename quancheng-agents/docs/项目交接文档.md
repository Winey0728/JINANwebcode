## 一、项目背景

山东大学团队项目「泉城水脉文化智能体」系列应用，依托**山东大学智能体平台**（HiAgent 火山引擎校内部署版）开发，最终通过 **Flipbook 网页嵌入**功能把智能体集成到数字画册中。画册每一页有固定的智能对话悬浮按钮，用户点击即可打开对话界面。

项目文档要求四个专门化智能体模块：

| # | 智能体 | 核心要求 | 平台能否独立完成 |
|---|---|---|---|
| ① | 泉城文化问答 | RAG 挂载知识库，限定只答济南水系文化；解答景点历史、文化内涵、交通路线、开放时间、周边美食；多轮对话 | ✅ 已完成配置 |
| ② | 多语种语音讲解 | 普通话/济南方言/英语三版语音；儿童版/故事版/专业版等风格；点击按钮即生成播放，不预录大量音频 | ⚠️ 平台无 TTS → 用 Kimi TTS 插件预生成音频文件挂到画册页面 |
| ③ | 个性化路线规划 | 按游览时间/兴趣偏好/体力状况/交通方式出路线；图文展示；可点击链接跳转画册对应景点页 | ✅ 平台可搭（对话型），链接清单需画册方提供 |
| ④ | 历史场景复原 | 生成济南老火车站、清末大明湖、民国商埠街景等复原图片/短视频；景点页加"历史复原"按钮 | ⚠️ 平台无图像/视频生成 → 用 Kimi 图像生成预生成成品 |

**关键策略**：平台模型普遍老旧（多为 2025 年上半年版本），老师要求用该平台搭建，团队决定内容生产（文案、语音、图像）用 Kimi 的强模型完成，平台只承载对话型智能体（①③）和知识库。

### 4.3 设计决策（已确认）
1. **类型**：对话型 + 提示词引导参数收集，不上工作流
2. **参数收集**：识别四参数（游览时间/兴趣偏好/体力状况/交通方式）→ 缺失亲切追问（一次最多 1–2 个）→ 未说明的用默认值并明示 → 用户改条件则增量调整
3. **输出格式**：时间轴分点（时段 ｜ 景点名+推荐理由+停留时长+交通衔接）；景点名带 Markdown 链接，现阶段一律用占位符 `[景点名](链接待补)`，画册链接清单到位后回填
4. **数据双轨**：全文底稿进「路线规划资料库」知识库（RAG 检索），推理骨架（老城簇步行可达+经典环线+体力映射）精简嵌入系统提示词
5. **知识挂载 4 个库**：泉水文化 + 古城墙 + 泉水周边考古遗址（历史深度差异化）+ 路线规划资料库
6. **插件**：加挂 BingSearch（免费）查时效信息，必须带免责口径；高德地图 MCP（付费）为进阶可选
7. **核心约束**：不编造景点/开放时间/票价；"暂未收录"字段 100% 按"以官方公告为准"口径；步行时间为估值需声明；餐饮只做街区级

## 八、操作经验（Kimi Code 续作时重要）

### 8.1 WebBridge 自动化操作该平台的坑
- 会话用 `session: "sdu-agentlab-recon"`；Windows 下必须写 JSON 文件再 `curl.exe --data-binary "@file"`，防中文损坏
- **提示词编辑器（contenteditable）用 `fill` 工具写入会"假成功"**（返回 success 但内容不变）——有效方案：evaluate 聚焦+全选编辑器，然后 `cdp Input.insertText` 注入全文
- 开场白等普通 contenteditable 用 `fill` 正常
- 快照 `@e` 引用在每次 snapshot 后刷新，跨操作复用会报 "unknown ref"，需重新 snapshot
- 平台会反复弹「引用了未定义的变量」对话框，用 JS 批量点可见的「取消」按钮清除
- 知识库卡片无文字按钮，加号在卡片 header 的 `.operation-icon`（blow-up 图标），点击后弹「添加知识库」对话框
- 开关状态检测：a11y 树不含状态，需 JS 查 `button.arco-switch` 的 aria-checked（但定位不太可靠，最终靠截图目视确认）

### 8.2 平台通用规则
- 草稿自动保存（页面顶部"草稿最后保存于 HH:MM:SS"可验证）
- 渠道配置修改后必须点右上角【渠道发布】生效；发布需管理员审批（教学标签）
- 智能体列表页卡片菜单：统计/复制/复制至其他空间/限流/观测管理/删除（无导出）
